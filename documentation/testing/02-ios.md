# iOS test script

This covers what is specific to iOS: the Files app and open in place, AirDrop and the Inbox, iCloud Drive, the share
sheet, the Keychain surviving an uninstall, background sync, appearance, the keyboard, VoiceOver and the App Store
rules. Platform-agnostic behaviour is in `00-core-functional.md`. Two-device sync is in `07-sync-multi-device.md`.

Tests marked **(iPhone)** need a real device. The rest run in the simulator, and on the iPhone too if time allows.
The iPhone is where the touch, the keyboard, AirDrop, iCloud Drive and the background task behave the way users will
meet them.

## Before you start

- **Simulator**: from the repository root,
  `xcodebuild -project app/ios/iosApp/iosApp.xcodeproj -target iosApp -sdk iphonesimulator -arch arm64 SYMROOT=<dir> OBJROOT=<dir> build`,
  then `xcrun simctl install booted <dir>/Debug-iphonesimulator/Campfire.app` and
  `xcrun simctl launch booted com.pandulapeter.campfire`. The container is at
  `xcrun simctl get_app_container booted com.pandulapeter.campfire data` → `Documents/library/…`.
- **iPhone**: open `app/ios/iosApp/iosApp.xcodeproj` in Xcode. Set your team in `iosApp/Configuration/Config.xcconfig`
  (not in the Signing tab: that would write a literal over `$(TEAM_ID)`). Pick the phone and Run. For the release
  configuration tests (IOS-080), use Product → Scheme → Edit Scheme → Run → Release.
- **Sync**: `campfire.dropbox.appKey=…` in `local.properties`. The Xcode build phase starts Gradle and reads it. Use
  a Dropbox account prepared as the README's "The Dropbox account" describes.
- **Fixtures**: generated by `documentation/testing/fixtures/make_fixtures.py` (see `README.md`). Get them onto the
  simulator by dragging files onto its window (they land in Files), and onto the iPhone with AirDrop or iCloud Drive.
- **Time**: about 1.5 hours for the smoke test and the P0/P1 tests; a full pass is half a day.
- **What to record**: for each failure, the test ID, the device and iOS version, a screen recording
  (Control Centre → Screen Recording), and the Xcode console output around it.

**Legend.** P0 = can lose or corrupt the library, or blocks the release. P1 = visible breakage. P2 = polish.

## Smoke test (10 minutes, every build)

- [ ] **IOS-S01** Delete the app, install it → the orange launch screen, then the song list with the two demo songs
  and the demo setlist.
- [ ] **IOS-S02** Open a song, transpose, swipe back from the left edge, open it again → the transposition is kept.
- [ ] **IOS-S03** Edit a song, type, Close → the unsaved changes question → Save → the text is in the viewer.
- [ ] **IOS-S04** Files → a `.cho` → Share → Campfire → imported and opened.
- [ ] **IOS-S05** Settings → About: author/version, GitHub, Report a problem, *Every version of Campfire*, the
  privacy policy. *Rate Campfire* is there only once the app has an App Store listing, and then opens it. There is
  **no** *Buy me a coffee* (App Review guideline 3.1.1).
- [ ] **IOS-S06** Settings → Library → Location says the Files app; Files → On My iPhone → Campfire → `library` shows
  the songs.

## 1. Library safety (P0 first)

- [ ] **IOS-001** (P0) Reinstall starts disconnected, uploads nothing
  1. Connect Dropbox and finish a first sync.
  2. Delete the app (the Keychain item survives this), then install it again from Xcode.
  **Expected:** the first launch offers Connect with no account shown. No run starts, and the Dropbox folder is
  unchanged (the demo songs are **not** uploaded). Connecting again downloads the library. Repeat with a library that
  had grown past the demo: it's still planted fresh and still disconnected.
  <sub>[r5-25]</sub>
- [ ] **IOS-002** (P0) Deleting the library folder in Files does not empty Dropbox
  1. Connect, sync 10+ songs. In Files → On My iPhone → Campfire → library, delete the `songs` folder. Reopen
     Campfire and *Sync now*.
  **Expected:** the run stops and asks: *Delete them from the cloud too* / *Keep them and download*. *Keep them and
  download* restores every song. Nothing is deleted from Dropbox without an answer.
  <sub>[r5-01]</sub>
- [ ] **IOS-003** (P0) Sync never writes over a save made during the run
  1. Connected, with ~200 songs; edit song X in Dropbox from a computer.
  2. On the phone, edit song X and save while a *Sync now* run is still going (Settings → Developer → Network Link
     Conditioner on the iPhone, or a large library, to stretch it).
  **Expected:** your saved edit stays in song X; the Dropbox version arrives as a ` (2)` copy or is handled as a
  conflict next run; your edit is never replaced or deleted.
  <sub>follow-up fix (sync save race)</sub>
- [ ] **IOS-004** (P0) A large export neither freezes nor half-exports **(iPhone)**
  1. Import fixture: a library over 10 MB. Settings → Export library, and keep dragging the list with a finger while
     it writes.
  2. Import the saved zip into a fresh install.
  **Expected:** the UI keeps drawing (Time Profiler shows no `writeToURL` on the main thread), and the zip re-imports
  every song. Cancelling the picker doesn't leave the app stuck.
  <sub>[r5-28]</sub>
- [ ] **IOS-005** (P0) A library export that could not read a song says so
  1. In the simulator, `chmod 000` one song file in the container, then Export library.
  **Expected:** the export fails with a message, or saves and names the file it skipped; the picker completes.
  <sub>[r5-06]</sub>
- [ ] **IOS-006** (P1) A 600 MB file in the library does not kill the app
  1. Copy fixture: the huge file into `Documents/library/songs` of the simulator container, then launch.
  **Expected:** the app starts, and the file is reported as too large rather than read.
  <sub>[r3-06]</sub>
- [ ] **IOS-007** (P1) An unreadable library file stops a sync run cleanly
  1. `chmod 000` a song in the container and *Sync now*.
  **Expected:** the run reports the storage problem, and the file is still on Dropbox.
  <sub>[r1-07]</sub>

## 2. Files app, AirDrop, iCloud Drive

- [ ] **IOS-010** (P1) AirDrop and Mail files are imported, and the Inbox is emptied **(iPhone)**
  1. AirDrop a `.cho` to the phone (or open one attached in Mail) → Campfire.
  2. Files → On My iPhone → Campfire.
  **Expected:** imported and opened. The `Inbox` folder is empty or absent after the app has been in the background
  once.
  <sub>[r2-51][r5-29]</sub>
- [ ] **IOS-011** (P1) An evicted iCloud Drive file is downloaded, not skipped **(iPhone signed into iCloud)**
  1. Put a `.cho` in iCloud Drive from the Mac. On the iPhone, Files → long press it → Remove Download.
  2. Share → Campfire (or Open in Campfire).
  3. Repeat with an evicted zip, and with a file the Mac is still uploading.
  **Expected:** each is downloaded and imported (never "1 file was skipped"). A file still uploading arrives whole
  or fails; it never arrives truncated. The original stays in iCloud Drive.
  <sub>[r5-30]</sub>
- [ ] **IOS-012** (P1) Opening a library file in place is a duplicate, not a change
  1. Files → On My iPhone → Campfire → library → songs → tap a song → Campfire.
  **Expected:** "… 1 already there"; the song is still in the library and the file is untouched.
  <sub>[r2-51][r5-30]</sub>
- [ ] **IOS-013** (P1) Editing the library from the Files app
  1. With Campfire in the background, rename or delete a song file in Files; return to Campfire.
  **Expected:** the list rescans on resume and shows the change.
  <sub>[app/ios]</sub>
- [ ] **IOS-014** (P1) An unreadable Inbox file is skipped and cleaned up
  1. Simulator: put a file in `Documents/Inbox`, `chmod 000` it, `xcrun simctl openurl booted file://…`.
  **Expected:** "1 skipped"; after the app goes to the background the file is gone.
  <sub>[r2-51]</sub>
- [ ] **IOS-015** (P2) A 50 MB zip AirDropped while the app is closed: the launch screen animates, and the import runs.
  **(iPhone)** <sub>[r2-51]</sub>
- [ ] **IOS-016** (P2) File types: `.cho` opens in Campfire by default; `.chopro .chordpro .crd .chord .pro` offer it;
  zip and txt are not claimed (they can still be imported from inside the app). <sub>[app/ios]</sub>

## 3. Share sheet, export and temporary files

- [ ] **IOS-020** (P1) No temporary files are left behind
  Watch `<container>/tmp` in the simulator throughout.
  1. Import two `.cho` through the app's Import. 2. Export a song and cancel. 3. Export a song and save.
  4. Export library. 5. Share a song to Files, complete it, dismiss.
  **Expected:** `tmp` is empty after each step (after the sheet has closed, for a share).
  <sub>[r5-29]</sub>
- [ ] **IOS-021** (P1) Share to Mail keeps the attachment **(iPhone)**
  1. Share a song → Mail → send it to yourself.
  **Expected:** the received attachment is the complete song, even though the app deletes its copy afterwards.
  <sub>[r5-29]</sub>
- [ ] **IOS-022** (P1) A share sheet that could not open is not reported as shown
  1. Share a song, cancel, and tap Share again while the sheet is still sliding away.
  2. Tap Share while the export picker is still dismissing.
  **Expected:** either the sheet opens, or nothing happens and the app stays usable (another Share works). No
  message claims it was shared, and no temporary file is left behind.
  <sub>[r5-27]</sub>
- [ ] **IOS-023** (P2) iPad simulator: the share sheet is a popover anchored to the app. <sub>[r5-27]</sub>
- [ ] **IOS-024** (P2) The import picker: swipe it down, then Import again → it opens; a double tap opens one picker.
  <sub>[r2-51][r3-10]</sub>

## 4. Sync on one device

- [ ] **IOS-030** (P0) Connect **(iPhone for the redirect)**
  1. Settings → Library → Connect → the system alert → Continue → the Dropbox sheet → Allow.
  **Expected:** back in Settings, connected, and the first sync runs.
  <sub>[r2-21][pub-ios]</sub>
- [ ] **IOS-031** (P1) Cancelling is not an error
  1. Cancel on the system alert. 2. Continue, then Cancel on the sheet.
  **Expected:** the Connect row with no error message in both cases.
  <sub>[r4-11]</sub>
- [ ] **IOS-032** (P1) The Keychain holds the connection
  1. Connect, relaunch → still connected. Disconnect → the Keychain item is gone (a relaunch stays disconnected).
  <sub>[r1-20]</sub>
- [ ] **IOS-033** (P1) Background sync and its notification **(iPhone preferred)**
  1. A few hundred songs to download. The first *Sync now* asks for notification permission → Allow.
  2. Swipe to Home → Notification Centre shows "Syncing" with a moving count; return → the notification is gone and
     the progress row shows. Leave again and let it finish.
  3. App language Hungarian → the notification is Hungarian.
  **Expected:** as listed; the notification disappears when the run ends.
  <sub>[r4-12][r3-44]</sub>
- [ ] **IOS-034** (P1) Background expiry is reported, not forgotten
  1. *Sync now* with a big download, Home, wait ~40 s (Xcode logs the expiration), return after 2 minutes.
  2. Kill the app from the switcher while it is suspended mid-run, start it.
  **Expected:** "interrupted" in both cases; *Sync now* then only downloads the rest. No run starts by itself.
  <sub>[r3-28]</sub>
- [ ] **IOS-035** (P1) A run that another device keeps contesting is not a success
  **(dev-assisted)** Keep changing one file on Dropbox during both passes of a run.
  **Expected:** the summary names the file, and "last synced" does not advance.
  <sub>follow-up fix (exhausted retries)</sub>
- [ ] **IOS-036** (P2) Names are composed (NFC)
  1. Create a song titled `Árvíztűrő` and one titled `Катюша` on the iPhone, and sync.
  **Expected:** on Dropbox, and on the Mac/Windows devices, each is one file (never two twins of different Unicode
  form). See `07-sync-multi-device.md` for the cross-device half.
  <sub>[r5-07]</sub>

## 5. Appearance, keyboard, VoiceOver, language

- [ ] **IOS-040** (P1) App theme overrides the system for the system UI
  1. System Light, app Dark → white status bar, dark document picker, dark keyboard, dark share sheet.
  2. System Dark, app Light → the reverse. 3. App "System default" → follows Control Centre's toggle each time.
  **Expected:** as listed; switching the theme in Settings flips the status bar with the cross-fade.
  <sub>[r3-22]</sub>
- [ ] **IOS-041** (P1) Keyboard
  1. Search open: rows clear of the keyboard and the fast scroller stops above it. Editor: caret on the last line
     visible. With the editor focused, trigger a snackbar.
  **Expected:** as listed; the snackbar sits above the keyboard.
  <sub>[r2-60][r4-36]</sub>
- [ ] **IOS-042** (P1) Gestures
  1. Edge swipe back from a song; double-tap the editor's Close; reopen the search while it is closing.
  **Expected:** swipe back follows the finger; a double tap leaves the song open (it does not also go back); the
  reopened search has the keyboard up.
  <sub>[r3-12][r3-36]</sub>
- [ ] **IOS-043** (P1) Right-to-left lyrics
  1. Import fixture: the Hebrew song with four chords per line. Open it in portrait and landscape.
  **Expected:** lines start at the right edge, and each chord sits over its own word; chords never pile up.
  <sub>[r5-35]</sub>
- [ ] **IOS-044** (P1) VoiceOver
  1. Setlist row: swipe up/down → Move up / Move down.
  2. A song: chorded lines are read with their chords, and tab blocks line by line.
  3. iPad: two columns are read in song order.
  **Expected:** as listed.
  <sub>[r4-30][r4-34][r4-37]</sub>
- [ ] **IOS-045** (P2) Largest accessibility Dynamic Type: setlist numbers keep the titles aligned. <sub>[r4-35]</sub>
- [ ] **IOS-046** (P1) Hungarian system language
  1. Simulator in Magyar, relaunch → the app is Hungarian, and so are the Connect Dropbox alert and the document
     picker's buttons.
  2. English system, Settings → Apps → Campfire → Language → Magyar, with the app on System default → Hungarian.
  **Expected:** as listed. A Hungarian system with the app set to English keeps the system sheets Hungarian; that's
  expected.
  <sub>[r4-15]</sub>
- [ ] **IOS-047** (P2) The screen doesn't dim while a song is open (and does elsewhere). **(iPhone)**
  <sub>[presentation]</sub>
- [ ] **IOS-048** (P2) Hardware keyboard or page-turner pedal on song details: arrows scroll and page; Cmd + arrows
  are left to the system. **(iPhone/iPad with a keyboard)** <sub>[r5-34]</sub>

## 6. Release build and App Store

- [ ] **IOS-080** (P1) The release build's identity
  1. Build Release and install. Check the home screen label, Settings → About's version, and the built
     `Info.plist`.
  **Expected:** the label reads "Campfire"; the version is `campfire.versionName` and the build number is
  `campfire.ios.buildNumber` (a `campfire.ios.buildNumber` in `local.properties` overrides it);
  `LSApplicationCategoryType` is `public.app-category.music`.
  <sub>[r5-22][r5-24]</sub>
- [ ] **IOS-081** (P1) The TestFlight build: Connect's `campfire://` redirect returns to the app, and a run carries on
  in the background. **(iPhone, TestFlight)** <sub>[pub-ios]</sub>
