# :presentation — ui/notation

Drawing the staff notation `:abc:api` renders, in common code with no SVG library: Skia's SVG DOM draws no `<text>`
and ignores `<style>`, and abc2svg writes every music symbol as text in its music font, styled by CSS class.

- **Only the subset abc2svg emits** is read (`svg`, `style`, `defs`, `g`, `use`, `path`, `circle`, `ellipse`, `text`,
  `tspan`; translate and uniform scale): `SvgXml.kt` reads the XML, `NotationCss.kt` the single-class rules (fonts,
  strokes, and what the modules add: anchors, a jazz chord's relative size and raised baseline, a box's outline),
  `NotationDrawingParser.kt` the rest into plain data (`NotationDrawing`, tested). **Anything else gives no drawing**,
  and the run stays text: better than notation with something silently missing. Checked against several voices,
  decorations, boxes, chord diagrams and grids, string tablature, jazz chords, Clairnote, and jianpu.
- Styles and `<defs>` are gathered across the systems of one rendering, never across renderings (see `:abc:api`).
- Music symbols are paths from `AbcMusicGlyphs.kt`, generated by `tools/fonts/abc_music_glyphs.py` from abc2svg's
  `font/abc2svg.sfd` and never edited by hand; the outlines stay under the font's OFL, which the file says.
- Words are drawn in the app's typeface (the lyrics' style, unscaled), at the size and weight the CSS gives (lyrics
  `LYRICS_ROOM` smaller, see `:abc:api`), placed by their baseline and anchor once measured; chord symbols in the
  second accent colour, everything else `onSurface`. Colours are given only when drawing (`drawNotationSystem`), so a
  theme cross-fade lays nothing out again.
- **Chord names are the page's** (`NotationChordNames.kt`, tested): the semitones are the lyrics' chords' (the file's
  `{transpose}` plus the reader's sounding transposition, `NotationChordSpelling`, carried by `SongLyricsModel`), and
  abc2svg moves the notes by them. abc2svg also renames every chord symbol whose first A–G letter it finds (it read
  "Do" as D), and annotations would zigzag, so its names are replaced in the drawing by the ones `:chordpro` gives the
  same symbols (spelling, notation, a numbering counted from the tune's first `K:`): **each drawn chord takes the name of
  the symbols it is a transposition of**, in whatever order abc2svg drew them, and one matching none (the capo
  module's line) or symbols named apart keeps abc2svg's. A tune under a mid-song `{transpose}` is moved by it too
  (`abcTuneOffsets`).
- A tune whose first `T:` is the song's title leaves its title and composer to the page (`AbcTitles.kt`, tested: a
  `%%writefields` line in that tune's header); the tunes of a medley, named otherwise, keep theirs.
- `NotationPainter` turns a drawing into merged paths and text layouts, laid out at the unit size it was rendered for.
  The screen's systems are painted with the rendering, off the main thread (the web's only thread aside), by a painter
  of each run of the rendering effect's own (`NotationPainting.newPainter`, its own `TextMeasurer`), and kept with the
  rendering; nothing is painted during composition. The PDF keeps a few painted drawings by drawing and scale.
  `rememberSongNotations` renders a song's `abc` runs off the main thread for a page as wide as the
  widest column, each unit `NOTATION_UNIT` (1 dp) times the text size, and again when the tunes, the transposition, the
  spelling, the width, or the text size change; a width or a text size alone waits 300 ms for the resize or pinch to
  settle, the systems scaled meanwhile (`SongNotationBlock`: the current unit, or smaller to fit the column). All tunes
  arrive at once, so the sections are measured again once; a rendering replacing one the reader changed cross-fades
  with it (fading in from nothing blinked the tune out) while the sections glide, the first one (replacing the text)
  does not. Until then, and for a tune that fails, the run is its monospace text. The
  renderer comes from `LocalAbcRenderer`, provided by `CampfireApp`.
- **Renderings are kept app-wide** (`NotationCache`, `LocalNotationCache` from `CampfireApp`: 16 tunes or 4,000 laid-out
  words, least recently used out), keyed per tune by everything they depend on (text, spelling, width, unit, title,
  painting), so a tune seen before at the same width, size, and transposition is notation on its first frame. A cold one
  is text until it arrives, and its arrival (`arrivingTunesOf`, `SongNotations.arrival`) moves nothing gradually; a
  rendering that also re-renders a tune is the reader's change and is narrated whole.
- **The engine is warmed** (`NotationEngineWarmUp.kt`) 2 s after the library first holds a song with an `abc` block
  (`Song.hasSheetMusic`, from the library scan), on every platform the web included, so a tune's first open pays only
  its rendering.
