# :presentation:shared

All UI logic and Compose components shared between Android, desktop and iOS. A Kotlin Multiplatform module (`campfire-compose-library`) — keep it free of JVM-only APIs (`java.*`, `KoinJavaComponent`); use `kotlin.uuid.Uuid`, `androidx.compose.ui.text.intl.Locale` and `KoinPlatform.getKoin()` instead. Depends only on `:domain:api`. Koin wiring in `Module.kt` (`presentationModule`) — `CampfireViewModel` via `viewModelOf`, obtained in Compose with `koinViewModel()`.

- `ui/CampfireViewModel.kt` — a lifecycle `ViewModel`. Exposes `StateFlow`s derived from `GetScreenDataUseCase` (`stateIn(viewModelScope, WhileSubscribed)`), the grouped song list (`songGroups`, section headers computed here so the UI never needs `NormalizeTextUseCase`), `setlistsWithSongs`, `visibleDialog`, and the Navigation 3 `backStack` (`SnapshotStateList<CampfireDestination>`). Intent handlers are non-suspend and launch in `viewModelScope`.
- `ui/CampfireApp.kt` — the root composable used by every platform shell: theme, language preference, adaptive chrome (`NavigationBar` under 600dp, `NavigationRail` above, side panel for filters from 840dp — see `components/WindowSize`), the `Scaffold` + `NavDisplay`, and `CampfireDialogs`. Tab switches use a fade-through transition; pushing/popping `SongDetails` uses the platform default of Navigation 3 (drives predictive back on Android and swipe back on iOS). The rail stays visible on the details screen; bars and side panels animate with expand/shrink so the content reflows fluidly.
- `ui/navigation/CampfireDestination.kt` — `NavKey`s: `Songs`, `Setlists`, `Settings` (top level) and `SongDetails(songIds, setlistId, initialIndex)`. Top level selection resets the stack to `[Songs, tab?]` so back always returns to Songs.
- `ui/screens/` — one package per destination. Screens own their `TopAppBar` (which handles the status bar inset) and get a `contentPadding` for the bottom/horizontal insets from the outer scaffold so lists scroll edge to edge.
- `ui/components/` — Material 3 list items (`SongListItem`, `SectionHeader`, `SwitchListItem`, `CheckboxListItem`, ...), `SearchField` (`SearchBarDefaults.InputField`), `SegmentedChoice`, `SongsControls` (sort + filters, used both as side panel and bottom sheet).
- `ui/dialogs/Dialogs.kt` — `CampfireDialogs` renders whatever `visibleDialog` asks for: new setlist / new database `AlertDialog`s, controls and setlist picker `ModalBottomSheet`s.
- `ui/theme/` — `CampfireTheme` (`MaterialExpressiveTheme`, animated light/dark switch), `CampfireColorSchemes` (orange seed palettes), `CampfireIcons` (path data).
- `ui/platform/Platform.kt` — `expect` declarations with `androidMain`/`desktopMain`/`iosMain` actuals: `PlatformVerticalScrollbar` (desktop only), `isDesktopPlatform` (no pull to refresh, refresh action in the app bar instead).
- `ui/theme/Language.kt` — `ApplyLanguagePreference` maps the user preference to the generated `AppLocale` and sets `currentLanguage`, which every `stringResource` call observes.
- `composeResources/values[-hu]/strings.xml` — all UI strings. The `com.hyperether.localization` Gradle plugin turns them into Kotlin string tables (`build/generated/compose/resourceGenerator/kotlin/commonCustomResClass`, package `com.pandulapeter.campfire.shared.localization`): `StringsDefault`, `StringsHu`, `AppLocale`, `currentLanguage`, `LocalizedStrings` and the language-aware `stringResource` overloads. Adding a new `values-xx` folder needs a clean build so the plugin regenerates `AppLocale`.
- `ui/components/CampfireTopAppBar.kt` — every screen's app bar: pinned scroll behavior plus an animated shadow/tint once content scrolls underneath (screens apply `nestedScroll(scrollBehavior.nestedScrollConnection)`). Sticky list headers are raised pills (`SectionHeader`) for the same reason.
- `screens/songDetails/SongLyrics.kt` — lyrics are split into sections and flowed into columns (`SongSectionsLayout`, min 360dp per column); sections are never split and animate between layouts with `animateBounds` inside a `LookaheadScope`.

**Raw song format** (parsed in `screens/songDetails/SongLyrics.kt`): `{c: Verse 1}` lines become section headers (title matched against known section names for localization), `[Am]` markers become chords rendered above the syllable they precede, everything else is lyrics.
